## 1. 背景与定位

### 1.1 问题

普通用户面对的三个真实困境：

1. **"这件衣服穿在我身上是什么样？"** 电商模特图不等于自己，买错成本高。
2. **"明天这个场合穿什么？"** 有衣服但不会搭，小红书式内容只能看不能试。
3. **"搭好了，想被认可 / 想找同好。"** 缺少低门槛的分享与讨论场所。

### 1.2 定位

**面向普通用户的 AI 穿搭决策工具 + 穿搭社区。**

- 工具价值：把"想象"变成"看见"——生成穿在**用户自己身体上**的全身效果图，并给出**可购买、可复用**的结构化单品数据。
- 社区价值：把"看见"变成"讨论"——方案一键分享，形成场景 × 风格的穿搭经验沉淀。

### 1.3 差异化

| 维度 | 传统试衣间 / 电商试衣 | 通用 AI 绘图 | OOTD Lab |
| --- | --- | --- | --- |
| 是否保真 | 只换衣服不换人 | 人像随机、身材漂移 | 保留面部特征与体型比例 |
| 是否可搭配 | 单件试穿 | 需要写 prompt | 衣橱可视化拖拽 + 场景推荐 |
| 数据是否结构化 | 商品维度 | 无 | 单品维度，可跨模式复用 |
| 是否可分享 | 弱 | 弱 | 原生社区（关联方案） |

### 1.4 目标与非目标（v1）

**目标**

- G1：用户 3 分钟内完成"上传 → 搭配 → 生成 → 保存"闭环。
- G2：AI 推荐结果中的单品 100% 带结构化数据（类别/颜色/材质/季节/风格）。
- G3：人脸等敏感影像"可授权、可撤回、可删除"，默认私密。
- G4：无任何第三方 Key 时，全站可本地跑通（Mock 生成）。

**非目标（v1 不做）**

- 不做真实电商交易、支付、物流；仅提供外链。
- 不做 3D 人体建模 / 视频试衣。
- 不做实时多人协作编辑。
- 不自建图像模型训练；不把用户照片用于训练。
- 不做独立 App（响应式 Web 优先，预留 PWA）。

## 2. 用户与场景

### 2.1 用户画像

| 画像 | 特征 | 核心诉求 | 关键路径 |
| --- | --- | --- | --- |
| 小美 · 22 岁 大学生 | 预算敏感，爱逛社区，手机为主 | 约会/面试穿什么，想先看效果 | AI 推荐 → 生成 → 分享 |
| 阿哲 · 29 岁 互联网从业者 | 衣柜单品多但不会搭，效率优先 | 通勤快速决策，复用已有衣服 | 自由搭配 → 保存方案 |
| 林姐 · 34 岁 品牌店主 | 有大量商品图，需要内容 | 用买家/模特图生成场景穿搭做种草 | 上传自有衣服 → 生成 → 发帖 |

### 2.2 核心场景（Job To Be Done）

1. **场景决策**：明天去海边约会 → 想要"轻盈、显白、不踩雷"的一套，含购买链接。
2. **单品验证**：看中一条半裙，用自己的全身照试穿，判断比例是否合适。
3. **衣柜复用**：已有白衬衫 + 牛仔裤，想加一件外套看整体效果。
4. **经验分享**：把生成的方案发到讨论区，配文"互联网公司面试穿这套稳了"，收获点赞与讨论。

### 2.3 用户旅程（首次使用）

```
落地页 → 浏览示例搭配（未登录可看）
      → 点击「开始搭配」→ 登录/注册
      → 引导：填身高体重/风格偏好（可跳过）+ 人脸授权说明
      → 上传全身照（裁剪/旋转）→ 勾选单独同意
      → 衣橱选 3 件 → 生成（异步，展示进度）
      → 结果页：效果图 + 单品清单 → 保存
      → 弹窗「分享到讨论区？」→ 发布 → 获得首个点赞（通知）
```

## 4. 功能详述与验收标准

> 验收标准（AC）采用「前置 → 操作 → 期望」。所有列表默认游标分页，默认 20 条。

### 4.1 账号与引导

**注册/登录**

- 邮箱 + 密码（≥8 位，含字母与数字），注册即创建 `User` + 默认 `Profile` + 默认 `handle`（`u_` + 8 位随机）。
- 会话使用 HttpOnly + Secure + SameSite=Lax Cookie（Auth.js JWT 策略），有效期 30 天，滑动续期。
- 连续 5 次密码错误锁定 15 分钟（按邮箱 + IP 维度）。
- 未登录访问受保护路由 → 跳转 `/login?next=...`，登录后回跳。

AC：
1. 已注册邮箱再次注册 → 409 `EMAIL_TAKEN`，表单行内提示。
2. 未登录调用 `POST /api/v1/outfits` → 401 `UNAUTHENTICATED`。
3. 登录后刷新页面会话保持；退出后受保护页 302。

**新手引导（3 步，可跳过）**

1. 身体数据：性别（含不愿透露）、身高 120–230cm、体重 30–200kg、体型（可选）。
2. 风格偏好：多选 ≤3 个 `StyleTag`；禁忌颜色多选。
3. 隐私说明：说明人脸图用途、存储方式、撤回方式；必须显式勾选才可进入上传。

AC：跳过引导仍可使用自由搭配（推荐质量降级提示）；已填写数据可在 `/me/settings` 修改。

### 4.2 自由搭配 Studio

#### 4.2.1 照片上传

- 支持 JPG/PNG/WebP/HEIC（服务端转码），≤10MB，最短边 ≥512，最长边 ≤8192。
- 前端：EXIF 方向校正 → 裁剪框（3:4 / 1:1 / 自由）→ 旋转（±90° 步进 + 滑杆 ±15°）→ 缩放 → 预览 → 上传。
- 上传流程：`POST /uploads/presign` → 直传对象存储（或本地 dev 端点）→ `POST /uploads/:id/complete`（服务端校验 magic bytes、尺寸、剥离 EXIF）→ 得到 `mediaId`。
- 人脸照可选：不传则仅保留体型、面部由模型补全（结果标注"面部为 AI 生成"）。

AC：
1. 超过 10MB → 前端拦截并提示"最大 10MB"；绕过前端时 API 返回 413 `FILE_TOO_LARGE`。
2. 上传非图片（改后缀）→ 415 `UNSUPPORTED_MEDIA_TYPE`。
3. 上传成功后 `MediaAsset.status = READY`，`visibility = PRIVATE`，`isSensitive = true`（人脸/全身）。

#### 4.2.2 人脸授权（合规硬门槛）

- 上传人脸照前必须勾选《人脸信息处理单独同意》，文案含：用途（仅用于本次/历史搭配生成）、存储（加密、私有）、保留期（默认 180 天）、撤回方式、不用于训练。
- 服务端记录 `Consent`：`type=FACE_IMAGE_PROCESSING`、`policyVersion`、`grantedAt`、`ipHash`、`userAgent`、`mediaAssetId`。
- 未授权上传 → 403 `CONSENT_REQUIRED`。
- 撤回授权 → 立即停止用于新任务，并异步删除所有人脸 `MediaAsset`（含对象存储），已生成结果保留但不再展示人脸原图。
- 人脸图**不进入任何 CDN 公共缓存**；读取必须 `purpose=face-preview` 且校验 owner，签名 URL TTL ≤ 60s，响应头 `Cache-Control: private, no-store`。

AC：
1. 未勾选 → 上传按钮 disabled，点击提示授权说明弹层。
2. 撤回后 5 分钟内 `/me/privacy` 显示"已删除"，对象存储文件不存在，任务创建返回 `CONSENT_REVOKED`。
3. 非本人访问他人 `facePhotoId` → 404（不泄露存在性）。

#### 4.2.3 站内衣橱

- 筛选维度：类别（上装/下装/连衣裙/外套/鞋/包/配饰）、颜色（16 色标签）、风格（14 类）、季节（春/夏/秋/冬/四季）、性别（女/男/中性）。
- 支持关键词搜索（名称/品牌/材质）。
- 分面返回各维度计数，空结果时推荐"放宽条件"（清除某维度）。
- 单品卡：图片（透明底抠图优先）、名称、颜色点、风格标签、价格（可选）、"加入搭配"按钮。
- 移动端：筛选收进底部抽屉，衣橱与画布切换 Tab。

AC：筛选组合生效且 URL 可分享（`?category=TOP&colors=BLACK,WHITE`）；滚动加载不重复（游标）。

#### 4.2.4 搭配画布

- 交互：点选"+"加入对应槽位；拖拽到画布任意位置；拖拽排序层级；双击置顶；Delete 删除；Ctrl/Cmd+Z 撤销。
- 槽位规则：`TOP` / `BOTTOM` / `DRESS` / `OUTERWEAR` / `SHOES` / `BAG` / `ACCESSORY`。
  - 连衣裙与上装/下装互斥；外套覆盖在上装之上；同一槽位可多件但仅一件"主件"。
- 坐标以图片归一化比例存储（0–1），保证不同分辨率一致。
- 校验：生成前至少 1 件；必须有底图；单套 ≤8 件。

AC：
1. 加入连衣裙后，上装/下装槽位置灰并提示"已选择连衣裙"。
2. 刷新页面/换设备打开同一 `outfitId`，图层位置误差 <1%。
3. 超过 8 件 → 按钮禁用 + toast。

#### 4.2.5 自有衣服上传与抠图

- 上传衣服平铺图 → 创建 `Garment`（`source=USER_UPLOAD`, `ownerId=me`, `status=DRAFT`）→ 异步抠图任务（`BG_REMOVAL`）。
- 抠图完成 → `cutoutId` 写入，`status=READY`，加入"我的衣服"衣橱分组。
- 抠图失败 → 保留原图可手动框选"保留区域"重试（P1），并提供"直接使用原图"降级。
- 用户上传的衣服仅本人可见，可删除。

AC：抠图任务 30s 内完成（Mock）；失败时 UI 展示重试 + 降级两个按钮。

#### 4.2.6 生成

- `POST /outfits/:id/generate`：校验授权/额度/单品规则 → 创建 `GenerationTask` → 入队 → 返回 `{ taskId }`。
- 前端每 2s 轮询 `GET /tasks/:id`，指数退避至 5s，页面隐藏时暂停；90s 未完成展示"仍在生成，可离开页面"。
- 生成中可取消（`POST /tasks/:id/cancel`）。
- 自动重试：网络/供应商 5xx 重试 3 次（退避 2s/8s/20s）；内容审核拒绝不重试。
- 降级链：主供应商失败 → 备用供应商 → **拼贴合成**（服务端按坐标把抠图叠加到底图上）。降级结果标注"预览版"。
- 超时：单任务 10 分钟未完成 → `FAILED / TIMEOUT`。

AC：
1. 无授权 → 403；无额度 → 429 `QUOTA_EXCEEDED` 并提示明日恢复时间。
2. 重复点击（同 Idempotency-Key）→ 返回同一 taskId，不重复扣额度。
3. 主供应商 500 两次 → 任务仍成功（降级），`output.degraded=true`，UI 显示"预览版"角标。
4. 生成完成 → 结果页展示效果图 + 每个单品的名称/类别/颜色/材质/风格/价格/品牌/链接。

#### 4.2.7 保存 / 重新生成 / 下载 / 分享

- 保存：`outfit.status` DRAFT → SAVED；标题默认"未命名搭配 · MM-DD"。
- 重新生成：可改"随机姿势 / 保留姿势"、"背景：原图/纯色/场景"，旧结果保留在历史（仅最近 3 次）。
- 下载：签名 URL，文件名 `ootd-{id}.png`；免费用户带右下角水印（P1 可关闭）。
- 分享：创建草稿帖并跳转编辑器，预填封面、正文模板、`#场景` `#风格` 标签、关联 `outfitId`。

AC：未保存的方案也可生成；下载链接 5 分钟过期且仅本人可获取。

### 4.3 AI 推荐

#### 4.3.1 输入

- 场景（必填，2–200 字），示例 chips：海边约会 / 互联网公司面试 / 朋友婚礼 / 秋冬通勤 / 音乐节。
- 可选：性别、身高、体重、风格偏好（≤3）、预算区间（0–500 / 500–1500 / 1500–3000 / 3000+）、城市、天气（晴/雨/雪/温度）、禁忌颜色（多选）、是否必须可购买。

#### 4.3.2 解析与推荐

- 解析（≤3s）：`occasion`（场景枚举）、`formality`（1–5）、`season`、`weather`、`keywords`、`riskFlags`（如"海边=防风/防走光"）。
- 召回：按 `category × season × style × gender` 过滤 `Garment`，预算硬过滤，禁忌色排除；每槽位 Top 20。
- 排序/组合：LLM 从候选中选一套，输出严格 JSON（`RecommendationDraft`），包含每件 `reason` 与整体 `rationale`、`stylingTips`、`avoidTips`。
- 无合适候选 → 允许"AI 虚拟单品"（`isAiGenerated=true`，无链接），或提示"站内暂无匹配，试试放宽预算"。

AC：
1. 输出必须通过 Zod Schema 校验，失败自动重试 1 次，仍失败则返回规则模板结果（不阻塞）。
2. 单品 `category` 组合合法（不能两条裤子；连衣裙不与上下装共存）。
3. 预算 500 元以内 → 结果总价 ≤500（AI 虚拟单品不计价但需标注）。
4. 禁忌色为黑色 → 结果不含 `BLACK` 主色单品。

#### 4.3.3 输出与操作

- 文字结果 8s 内返回并渲染；效果图异步，占位骨架 + 进度。
- 结果页：风格标题、整体理由、场景标签、搭配清单（可点开单品详情）、"换一套"、"收藏"、"保存为方案"、"分享到讨论区"、"重新生成图片"。
- 换一套：排除当前 `garmentIds`，最多 5 次/日/用户；保留输入条件。
- 收藏：写入 `OutfitFavorite`，在 `/me/favorites` 可见。

AC：换一套后至少 60% 单品不同；"保存为方案"后出现在 `/me/outfits` 且可二次编辑。

### 4.4 讨论区

#### 4.4.1 发帖

- 字段：标题 5–80 字、正文 ≤5000 字（支持换行，不支持 HTML）、图片 1–9 张（≤10MB/张）、标签 ≤5（可新建）、场景标签 ≤3、关联方案（仅自己的或公开的）。
- 发布前校验：敏感词、图片机审、频率限制（10 帖/日，间隔 ≥30s）。
- 状态机：`DRAFT → PENDING_REVIEW → PUBLISHED / REJECTED`；命中高危词直接 `REJECTED` 并提示修改。

AC：
1. 正文含敏感词（如"代购加微信"）→ 422 `CONTENT_BLOCKED`，高亮命中片段。
2. 图片审核 `REVIEW` → 帖子仅作者可见，显示"审核中"；管理端通过后转公开。
3. 关联他人私密方案 → 403 `OUTFIT_NOT_SHAREABLE`。

#### 4.4.2 浏览

- 信息流 Tab：推荐（热度）、最新、关注。
- 热度公式：`score = (like*3 + comment*5 + bookmark*4 + view*0.1) / pow(hoursSincePublish + 2, 1.5)`，每小时重算 Top 500 缓存 10 分钟。
- 卡片：封面（1:1 裁切）、标题、作者、标签、点赞/评论数、关联方案角标。
- 详情页：图片轮播、正文、单品清单（若关联方案）、评论区（一级 + 回复）、相关推荐。
- 搜索：标题/正文 ILIKE + 标签精确；结果按相关度 + 时间。

AC：信息流首屏 <1s（缓存命中）；无内容时展示引导发帖；举报入口在详情页"..."菜单。

#### 4.4.3 互动

- 点赞/收藏：toggle，唯一约束（`userId + postId`），计数用事务内 `increment`，每日上限 200 次点赞。
- 评论：≤500 字，支持一级回复；作者可删除自己评论；楼主可删除自己帖子下评论（软删）。
- 关注：不可关注自己；关注后信息流"关注"Tab 出现其内容；被关注者收到通知。

AC：重复点赞不重复计数；并发点赞（同用户双击）最终一致；删除帖子后详情 404，信息流不再出现。

#### 4.4.4 内容安全

- 三层：① 本地敏感词（`SensitiveTerm`，BLOCK/REVIEW 两级）；② 图片机审（Provider 接口，Mock 默认 PASS，支持手动触发 REVIEW）；③ 人工举报 + 管理员下架。
- 举报原因：色情低俗 / 违法违规 / 血腥暴力 / 侵权盗图 / 广告引流 / 人身攻击 / 其他。
- 管理员可：忽略 / 下架（`status=REMOVED`，通知作者）/ 封禁用户（7/30/永久）。
- 所有管理操作写 `AuditLog`。

AC：被下架帖子作者收到通知与理由；举报处理有状态流转与处理人记录；同一帖子被举报 ≥5 次自动进入优先队列。

### 4.5 个人中心与隐私

- `/me`：概览（方案数、获赞数、关注/粉丝）。
- Tab：我的搭配（草稿/已保存）、我的收藏（方案 + 帖子）、我的帖子、设置。
- 隐私中心：
  - 授权记录列表（类型、版本、时间、状态）。
  - 撤回人脸授权 → 级联删图。
  - 单张人脸图删除。
  - 导出数据（异步任务，生成 JSON 压缩包，24h 有效）。
  - 注销账号：二次确认 + 输入邮箱；软删，30 天后物理清理；期间可撤销。

AC：注销后立即无法登录；30 天内联系客服可恢复；到期后邮箱可重新注册。

### 4.6 管理后台（最小可用）

- `/admin`：概览（DAU、生成成功率、待处理举报）。
- `/admin/reports`：队列、筛选、详情、处理。
- `/admin/posts`：搜索、下架/恢复。
- `/admin/garments`：列表、新建/编辑、CSV 导入、上下架。
- `/admin/tasks`：失败任务、重试、供应商耗时分布。
- 权限：`role=ADMIN`；所有接口二次校验；操作审计。

### 4.7 通知

- 类型：生成完成/失败、点赞、评论、关注、系统公告、审核结果。
- 站内红点 + 列表；已读状态；P1 接邮件。

## 5. 非功能需求

### 5.1 性能

| 指标 | 目标 |
| --- | --- |
| 首屏 LCP（4G） | < 2.5s |
| 非生成 API P95 | < 500ms |
| 衣橱列表（1000 单品） | P95 < 300ms（含分面） |
| 生成任务（Mock） | P95 < 3s |
| 生成任务（真实供应商） | P95 < 45s，超时 10min |
| 图片体积 | 列表缩略图 ≤80KB（WebP），原图 ≤4MB |

### 5.2 可用性与容错

- 目标可用性 99.5%（生成服务单独降级，不拖垮浏览）。
- 生成供应商故障 → 自动切换 + 拼贴降级，UI 明示。
- 数据库故障 → 只读降级页；Redis 故障 → 任务转 inline 或排队等待，不丢单。
- 所有写接口幂等（Idempotency-Key 或唯一约束）。

### 5.3 安全与隐私

- 传输 TLS 1.2+；HSTS；Cookie HttpOnly/Secure/SameSite。
- 密码 bcrypt(cost=12)；登录限流；CSRF 由 SameSite + Auth.js 保障。
- 人脸/全身照：AES-256-GCM 信封加密（每文件 DEK，KEK 在 KMS/环境变量），私有桶，禁止公开读。
- 最小化收集：不采集身份证、精确位置；IP 仅存 hash。
- 权限：所有资源查询带 `ownerId` 条件；管理端 RBAC；对象 key 不可枚举（UUID）。
- 内容安全：见 4.4.4；上传文件做 magic bytes 校验与图片重编码（防 polyglot）。
- 合规：单独同意、告知目的/期限、可撤回/删除/导出、不用于训练、数据留在所选区域；隐私政策与用户协议独立页面。

### 5.4 兼容与无障碍

- 浏览器：Chrome/Edge/Safari 最近两版，iOS Safari 16+，Android Chrome 110+。
- 断点：`sm 640 / md 768 / lg 1024 / xl 1280`；移动优先。
- 无障碍：键盘可达、焦点可见、对比度 ≥4.5:1、图片 alt、表单 label、`prefers-reduced-motion`。

### 5.5 SEO 与分享

- 公开帖子/方案可被索引（`generateMetadata`、OG 图、sitemap、robots）。
- 私密内容 `noindex`；分享链接使用不可猜测 ID。

## 7. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 虚拟试衣保真度不足（脸/身材漂移） | 核心价值受损 | 选型优先 IDM-VTON/Fashn；失败降级拼贴；结果页声明"AI 生成，仅供效果参考"；提供"保留面部"开关 |
| 生成成本失控 | 毛利为负 | 每日额度、分辨率档位、缓存相同输入、供应商比价路由、降级免费 |
| 人脸数据泄露 | 合规灾难 | 加密 + 私有桶 + 短签名 URL + 最小权限 + 审计 + 可删除；不做公网展示 |
| 用户上传他人照片 | 侵权/骚扰 | 上传即声明权属；举报通道；高风险账号人工复核；保留删除权 |
| 内容审核漏放 | 监管风险 | 三层审核 + 人工兜底 + 敏感词热更新 + 先审后发（新用户前 3 帖） |
| 冷启动无内容 | 社区空转 | 官方种子内容（Mock 生成示例）+ 生成即分享引导 + 话题活动 |
| 供应商锁定 | 议价/稳定性 | Provider 抽象 + 统一输入输出契约 + 双供应商热备 |
| 服装图版权 | 法律风险 | 站内素材需授权；用户上传仅自用；对外分享需确认 |
